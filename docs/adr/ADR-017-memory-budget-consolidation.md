# ADR-017: 记忆预算压力整理 —— MEMORY.md 达 90% 自动压缩

- 状态: Accepted
- 日期: 2026-09-15
- 关联: 修订 [ADR-016](./ADR-016-memory-v5-memory-md.md)（双卡点管家的触发条件）；沿用其机械门与单飞写入契约

## 背景

ADR-016 的 MEMORY.md 是「全量注入」的单一文件，写入端有 4000 tokens / 120 行硬顶。实际使用暴露了三个结构性问题：

1. **到顶即僵死**：文件写满后再来的稳定事实，管家必须整存整取重写整个文件；只要模型输出仍超顶，`max-tokens` 机械门就把整次重写拒掉——新事实永远写不进，文件长期钉死在 4000/4000。
2. **提示词不知道预算**：系统提示词只约束「≤100 行」，从不告诉模型 token 硬顶与当前用量；对中文高密度条目，100 行完全可能超过 4000 tokens，输出被整体拒绝时模型也无从收敛。
3. **两个卡点都可能缺席**：交付卡点靠信号门（用户线索 / 禁令 / 记忆候选 / 验证命令），压缩前卡点靠「真的发生压缩」。两者的空窗期里，文件到顶没有任何兜底。

真实事故：某项目 MEMORY.md 在 9/14 的压缩后恰好写满（3999/4000 tokens）；此后一整天十余个回合、一次压缩，记忆再未更新——压缩前管家跑过，但整存整取重写被硬顶拒绝（或判 NO_CHANGE），且审计只存内存，重启后无从查证。

## 决策

### 1. 压力线与目标线（`memoryFile.ts`）

- 触发线 `MEMORY_MD_CONSOLIDATION_RATIO = 0.9`：tokens ≥ 3600 或行数 ≥ 108 即 `overPressure`；
- 目标线 `MEMORY_MD_TARGET_RATIO = 0.8`：整理模式的机械输出上限 ≤ 3200 tokens 且 ≤ 100 行（更新模式与面板保存仍只用 4000/120 硬顶）；
- `getMemoryMdPressure(content)` 与写入校验同口径（trim + `estimateTokens`），纯函数、无副作用。

### 2. 管家 `consolidate` 模式（`memoryCuratorRunner.ts`）

- 新增 `mode: 'update' | 'consolidate'`（默认 update）；consolidate 追加系统提示词附录（三语）：合并重复/同族条目、精简冗长、删除过时或可即时探测的条目，稳定事实一条不丢。压不回目标线的输出由机械门拒绝，不靠模型自觉写 NO_CHANGE。**允许空素材**（纯整理不依赖新事实）。
- `buildCuratorUserPrompt` 恒注入当前用量。更新模式的输出上限是硬顶（4000/120）；整理模式的输出上限是目标线（3200/100），并写明超过会被拒绝、不会落盘。
- 机械门按模式分开。更新模式仍是「零新增且删除过半」拒写。整理模式：超过目标线拒写（`over-target`）；旧单元留下不足一半、且新文本也不是这些旧事实的子集时拒写（`consolidate-wash`）。原文保留、只删过时条目，允许超过一半。密钥、注入、硬顶与单飞写队列不动。

### 3. 触发（`memoryTurnPipeline.ts`）

- **交付卡点**：先读一次文件判定压力。未超压且信号门命中走 update；超压则无论有没有信号都走 consolidate（有新事实就一并合并）。
- **压缩前卡点**：仍然无条件运行；`overPressure` 时切 consolidate，折叠内容照常合并。未落盘同样记入节流墙，避免紧接着的测试回合再烧一次。
- **节流墙**：整理未落盘（nochange / rejected / failed / timeout / skipped）时记录当时的文件内容。文件未变时，无信号与「只有成功的测试/构建命令」都不再触发。显式记住、持久禁令、Agent「记忆候选」可以破墙。成功落盘后清墙——若写入后仍超压力线，下一回合再整理一次。
- Ask 模式维持永不触发（与 ADR-016 一致）。

### 4. 审计落盘

每次动作（含 skipped）追加一行 JSON 到 `.CodePapr/logs/memory-curator.log`（滚动保留最近 20 条，best-effort）：时间 / 卡点 / 模式 / 结果 / 原因 / 当时用量。内存审计（面板状态行）不变——重启即失的状态不再让「为什么没整理」无法查证。

## 后果

- **到顶不再靠「删一半就被拒」卡住**：整理模式可以删掉过时条目，只要留下的文本仍对得上旧事实，并且结果落在目标线以下。
- **成本有界**：压力触发的整理只在 ≥90% 时发生。未落盘后，后续测试回合不再每次重试；只有新的显式记忆意图会再花一次 fast 档调用。
- **行为可解释**：面板状态行 + 落盘日志共同回答「哪次卡点跑了、模式是什么、为什么被拒」（`over-target` / `consolidate-wash`）。
- **不把洗记忆放宽成改写**：更新模式的 mass-drop 原样保留。整理模式拦住的是「新文本对不上旧事实」的替换，不是「删掉一半原文」。模型交不回目标线以内的文本时文件保持原样，日志留痕，用户可在面板手动整理。
- 文档同步：`docs/USAGE.md` / `USAGE.en.md` / `docs/web/tool-inventory(.en).html` 的记忆章节与面板提示词。
