CONTEXT WINDOW · CACHE-FIRST

Context Layering · Three Tiers by Byte Stability

DeepSeek prefix caching matches the request body byte-by-byte from the front — the more stable the prefix, the higher the hit rate. CodePapr splits context into three tiers: a frozen stable prefix, session state rewritten on compaction, and append-only active context. RES
Tool Result
truncateToolOutputwrite-time 3-tier
append · bounded at birth
>100k chars → spill to disk + 2k preview + path (read can re-read); 60k–100k → middle truncation (head + tail, 20k total kept); 150k hard ceiling. Normalized and frozen once at write time, post-hoc sliding trim abolished → no more mid-prefix flips. Separately, tool context mode (full / summary / auto, default full) governs history only: the current round always receives the full output; once a result becomes history it is replaced by a structured summary card frozen at write time (applyHistoryToolSummaries; the latest batch stays full) — each message flips once (a one-time cache invalidation), and auto mode summarizes only above 5k chars. Code retrieval (read / grep / graph / lsp) is the most common tool result source.
This is the core of hit-rate optimization: every tool result is bounded at birth, the tail is naturally controlled, and miss converges to the theoretical minimum. Thresholds are in characters (content.length), so CJK text isn't misjudged by byte count. Rebuilds read frozen tool output directly (sortedStringify guarantees byte-identical with the live path).

Five Key Mechanisms

The underlying designs that turn "layering" into actual hit rate.
M·01
Freeze Outside Signature

memory.md and project-graph are volatile on disk but excluded from bootstrapSignature. resolveSessionBootstrap memoizes the bootstrap by (session × stable signature) — disk changes don't rebuild, updates take effect next session. Preserves the entire prefix cache.

M·02
Write-Time 3-Tier Truncation

Tool output is normalized once before writing to AppendOnlyLog (truncateToolOutput): 60k middle truncation / 100k disk spill / 150k hard ceiling. Bounded at birth, post-hoc sliding trim abolished, rebuilds byte-identical. Tool context mode (full/summary/auto, default full) is decoupled from truncation: the current round always receives full output, and history is folded into write-time frozen summaries.

M·03
Compaction Epoch

When rounds or tokens exceed limits, earlier messages are folded into a checkpoint summary + retained tail, opening a new context epoch. This is an intentional full prefix rewrite — accepting one invalidation in exchange for controlled context. The checkpoint is inserted at the retention boundary (not appended at the end); the recent tail after it stays verbatim (including tool-call↔result pairs). The boundary is chosen at UI-message granularity, so assistant+tools groups are never split. In the effective context the checkpoint is emitted as a user turn, avoiding a leading/consecutive assistant after compaction for better cross-provider correctness.

M·04
Dynamic Content Tail Isolation

Date, timezone, diagnostics, and other volatile content only enter the tail user message, never the prefix. The prefix only holds "session-invariant" content — this is the prerequisite for prefix caching to work.

M·05
Sub-Agent Context Inheritance

Sub-agents inherit the main session's skills, memory, project-graph, and customPrompt via SubagentSessionDeps, injected into their own Session Bootstrap. The bootstrap is injected with role: assistant + metadata.isPrefixSystem: true — the Claude provider extracts it as system content, avoiding a 400 error from a non-user first message; DeepSeek/OpenAI send it as-is.
