TOOL SURFACE · LSP / AST Inventory

Tool Inventory · Two-Layer Architecture × Language Intelligence

CodePapr exposes 25 merged tools to the LLM (graph is now UI-only), routed by dispatchers to 61 fine-grained workspace_* tools (hidden from the LLM), ultimately landing on the Tauri / Rust backend. Code intelligence (the lsp tool's 9 navigation actions) is wired to an LSP → AST project-graph fallback, tagged with source/confidence for precision; list browses the directory tree with per-file lightweight symbols (AST); read supports a symbol param for AST-based symbol reading and auto-attaches outlines for large files; grep supports semantic:true for LSP workspace symbol search. write / edit / patch now also layer AST syntax pre-checks and post-write LSP diagnostic feedback on top of text matching (matching stays literal, but ambiguity errors list each match's line and enclosing symbol). Text + AST
Reads a project file. Supports startLine/endLine line ranges, an aroundLine window, and maxBytes (defaults to 500KB). Pass symbol to read a specific symbol via AST targeting (degrades to text search without AST). Large full-file reads auto-attach a symbol outline.
Dispatch: read → workspace_read_file → invoke('read_text_file'). With symbol, first runs extract_file_symbols (AST) to locate the symbol's line range, then slices. Output passes through truncateToolOutput: >60k chars middle-truncated / >100k offloaded to disk + 2k preview / 150k hard cap.
WRITE
write→ workspace_write_file · workspaceTools.ts:2370
invoke write_text_fileastPreChecklspDiagnosticsHooknotifyWorkspaceMutation
Text + AST/LSP
Creates or fully overwrites a file. Runs an AST syntax pre-check before writing (rejects without persisting if new syntax errors appear), re-reads to verify consistency after writing, and syncs the LSP then returns the file's latest diagnostics (result includes diagnostics/notes).
Dispatch: write → workspace_write_file. Pre-write astPreCheck (tree-sitter compares before/after syntax error counts, rejects only when the count increases); post-write re-read verification + lspDiagnosticsHook (first lsp_open_document syncs the new content to trigger didChange, then lsp_get_diagnostics waits for the file's fresh diagnostics); finally editHistory.record + notifyWorkspaceMutation([path]) (also clears the graph build cache).
EDIT
edit→ workspace_apply_patch · workspaceTools.ts:3875
applySearchReplacePatchlocateSearchOccurrencesastPreCheck · lspDiagnosticsHook
Text + AST/LSP
Precise single-file SEARCH/REPLACE. Literal String.indexOf matching (CRLF→LF normalized), zero fuzzy; on multiple matches it errors out listing each match's line + enclosing symbol. AST pre-check before writing, re-read verification and LSP diagnostics after (maxBytes 20MB).
Matching semantics: search must match byte-for-byte; expectedOccurrences validates the count; multiple matches require replaceAll. On ambiguity it no longer just says "matched N occurrences"—locateSearchOccurrences pinpoints each line and extractProjectMapSymbols (AST) resolves the enclosing symbol, throwing a rich error with L<line> (in <kind> <name>) for precise disambiguation. Post-change lspDiagnosticsHook returns the file's latest diagnostics.
PATCH
patch→ workspace_apply_diff · workspaceTools.ts:3956
applySearchReplaceDiffmulti-file atomicastPreCheck · lspDiagnosticsHook
Text + AST/LSP
Multi-file atomic SEARCH/REPLACE: all patches are written together only after every one matches exactly; any failure rolls back. Matching mechanism is identical to edit (literal + ambiguity error with line/symbol), with per-file AST pre-check and LSP diagnostics, only adding cross-file atomicity.
Dispatch: patch → workspace_apply_diff. Re-reads source per file → per-patch ambiguity pre-check (locates line + symbol against running content) → applySearchReplaceDiff applies sequentially → per-file astPreCheck + write + re-read verification + lspDiagnosticsHook → batch notifyWorkspaceMutation (clears the graph cache).

Searches file contents by regex — the default tool for searching file content (strings, identifiers, log templates, config keys, you name it). contextLines defaults to 0, max 8; maxResults defaults to 80. semantic:true switches to semantic mode (LSP workspace symbol search); degrades to regex with a note when no LSP is available. LSP → AST
Read-only language-service navigation and analysis, 9 actions: goToDefinition / findReferences / hover / documentSymbol / workspaceSymbol / goToImplementation / prepareCallHierarchy / incomingCalls / outgoingCalls. Each action is LSP-first; when LSP is unavailable or returns nothing it automatically degrades to the AST project graph (a graph query), with results tagged by source(lsp/ast) and confidence(high/medium/low) precision. Requires file:line (:column optional).
Dispatch: lsp → createDefaultLspHandler → workspace_symbol_definition/references/hover/.... The AST fallback is symbol-level (graph symbols have line numbers only, no column), confidence=medium.
