Stable Prefix 稳定前缀

字节级冻结 · 整个会话最大缓存区
命中率最高会话内逐字节不变
ImmutablePrefix 不可变前缀对象 · prefix.systemPrompt / tools / params
SYS
System Prompt系统提示词
buildRuntimeSystemPromptruntimeSystemPrompt
冻结
模型身份与行为总纲：身份 + 核心原则 + 模式 intro + workspace + 核心约束 + 工具约束。构造 ImmutablePrefix 时校验禁止任何动态内容（时间戳 / 模板变量直接抛错），并一次性计算 SHA256。
注入链路：settings + rulesSection + mode → buildRuntimeSystemPrompt → ImmutablePrefix.systemPrompt → 请求 messages[0]。前缀哈希在每次 build 时被 RequestBuilder 校验不可变。
RULE
Runtime Rules项目规则
.CodePapr/AGENTS.mdbuildProjectRulesSection
冻结
全项目规则，所有模式与子代理都继承。工作区打开时载入并缓存于 _projectRulesSection，注入系统提示词。opt-in 文件：只有用户在「配置」面板保存规则时才创建 .CodePapr/AGENTS.md，否则为空、不注入。
注入链路：.CodePapr/AGENTS.md → projectConfigLoader.ts:loadProjectRulesSection → agentStore._projectRulesSection（缓存）→ buildRuntimeSystemPrompt({ rulesSection }) → promptSystem.ts:1168，位于 identity/principles 之后、mode prompt 之前。子代理通过 UiTaskToolContext.rulesSection 继承。

入口：顶部「配置」按钮 → ProjectConfigModal 的 AGENTS.md 标签页编辑保存；文件不存在时用模板预填。注意与 .CodePapr/agents/*.md（子代理定义）区分——后者变成 task 工具，不是规则。
TOOL
Tool Schema工具定义
ToolRegistry.getAll()按名排序 + canonical
冻结
会话开始时冻结全部工具定义（名称 + 描述 + 规范化参数）。工具集变化（MCP 加载、task 工具出现）会整体失效前缀——应由用户操作显式触发，避免隐性 churn。
RequestBuilder 每次 build 校验 tools 不可变（validateToolsImmutable），并对比运行时工具与冻结前缀一致（validateRuntimeToolsMatchPrefix）。
PARAM
Model Params模型参数
temperature / topP / maxTokens / thinking
冻结
参与前缀哈希。用户主动调参（调 temperature、切换 thinking）= 一次有意的整体失效，属可接受代价；系统不应在会话中隐式改参。
reasoning_content 回传按「历史消息是否存在」决定，与每轮 thinking 开关解耦，避免重建时给历史增删字节（DeepSeekProvider）。
Session Bootstrap 会话引导 = log[0] · role: assistant + metadata.isPrefixSystem（Claude 提取为 system）· resolveSessionBootstrap 按 (session × 稳定签名) 记忆化
SKL
Skills 摘要技能目录
.CodePapr/skills/*buildSkillsSection
签名内
只注入名称 + 一句话描述，稳定且小。全文由模型按需调用 skill_load 工具读取，作为工具结果落在尾部——不进前缀。增删 skill 是用户操作（在签名内），触发一次重建。子代理通过 SubagentSessionDeps.skillsSection 继承。
设计意图：「稳定上下文里只注入名称和描述，由模型自行判断是否需要，再按需调用 skill_load 读取完整说明」。
MEM
Stable Memory项目记忆
.CodePapr/memory.mdmemorySection
签名外冻结
跨会话项目知识，渲染为「## 项目记忆」。自动创建（冷启动 bootstrap）。通过 resolveSessionBootstrap 在轮次间冻结（签名外 → 前缀缓存不破）。mid-loop 压缩时刷新：上下文超预算触发压缩、epoch 重置时，refreshBootstrap 从磁盘重读 memory.md 并注入一份新的 bootstrap——反正 epoch 要重写，没有额外缓存开销。其余情况更新次会话生效。子代理通过 SubagentSessionDeps.memorySection 继承。
对比：项目里 memory.md 往往存在（自动生成）而 AGENTS.md 可能不存在（需用户保存规则）——两者创建机制不同。
CUS
Custom Guidance长期附加指导
settings.systemPromptcharacter prompt
签名内
用户自定义全局指导 + 角色设定，渲染为「## 长期附加指导」。作为附加约束生效，不覆盖系统级规则。settings.systemPrompt 可在设置 → 高级分页编辑；角色提示词通过 CharacterModal 设置。
与 Runtime Rules 区别：rules 来自项目文件（AGENTS.md），custom 来自用户设置 + 角色；两者都在稳定区。子代理通过 UiTaskToolContext.customPrompt 继承。

Session State 会话状态

慢变化压缩 epoch 重写

CKPT
Conversation Summary检查点摘要
renderContextCheckpointContent9 个 section
epoch 重写
被压缩的历史，作为单条 assistant 消息注入：用户目标 / 约束 / 已完成工作 / 重要文件·命令·错误 / 假设 / 验证状态 / 任务清单 / 待办 / 待确认问题。其中约束、假设与验证结论（即"已知决策"）由压缩模型从原始对话 + 工具结果中提取，不是独立注入点，而是 renderedContent 的内部 section。由轮数上限或 token 上限触发压缩时生成，替换掉更早的原始消息。
触发器是两个用户设置：maxConversationRounds（对话轮数上限）与 maxContextTokens（输入上下文上限），共同决定 shouldCompact。压缩 = 开启新 context epoch，接受一次前缀失效。本地兜底用正则抽取（buildLocalContextCheckpointSections），可选 LLM 增强生成结构化 sections。

PLAN
Live Plan实时任务清单 · Todo
renderTodoListDigest注入 user prompt 尾部
每轮实时
每轮从 live TodoListContext 渲染的实时摘要（目标 + 各任务 status/title/error），由 buildRuntimeUserPrompt 追加到 user prompt 尾部。始终反映当前计划状态，零额外缓存成本（user prompt 本身就在 miss 区）。压缩后下一条 user message 自带 live digest，无需单独冻结快照。
有损快照：仅含 status / title / retry / errorLog 前 200 字符，不含 description / dependsOn / artifacts。完整细节在 live 期间靠 todo 工具每轮回传。checkpoint.payload.todoDigest 仍存储（数据兼容），但不再单独注入为 user 消息。

project graph 缓存buildProjectGraphBootstrapSummary每轮注入

用户本轮输入（即当前任务）+ 运行时上下文（日期 / 时区）+ 项目诊断 + 实时任务清单，由 buildRuntimeUserPrompt 包装成一条 user 消息。所有动态内容刻意放在尾部，与前缀隔离——这是缓存安全的关键设计。已消费的图片会被剥离，避免 base64 反复膨胀后续请求。

RES
Tool Result工具结果
truncateToolOutput写时三阶梯
追加 · 出生即有界
>100k 字符 → 落盘 + 2k 预览 + 路径（read 可回读）；60k–100k → 中间截断（头尾共 20k）；150k 硬上限。模式由工具上下文设置控制（完整 / 摘要 / 自动）——自动模式在 5k 字符以下保留完整输出，超出则摘要。写时一次性归一化并冻结，废除事后滑动裁剪 → 前缀不再中部翻转。代码检索（read / grep / graph / lsp）是最常见的 tool result 来源。
这是命中率优化的核心：每条工具结果出生即有界，尾部天然受控，miss 收敛到理论下限。阈值按字符（content.length），中文不被字节数误判。重建时直接读取已冻结的工具输出（sortedStringify 保证与实时路径逐字节一致）。

五个关键机制

让"分层"真正转化为命中率的底层设计。
M·01
签名外冻结

memory.md 与 project-graph 在磁盘上易变，但被排除出 bootstrapSignature。resolveSessionBootstrap 按 (session × 稳定签名) 记忆化 bootstrap——磁盘变化不重建，更新次会话生效。保住整段前缀缓存。

M·02
写时三阶梯截断

工具输出在写入 AppendOnlyLog 前一次性归一化（truncateToolOutput）：60k 中间截断 / 100k 落盘 / 150k 硬上限。出生即有界，废除事后滑动裁剪，重建逐字节一致。可配置中间截断保留字符数（默认 20k）与工具上下文模式（完整/摘要/自动）。

M·03
压缩 Epoch

轮数或 token 超限时，把较早消息折叠成 checkpoint 摘要 + 保留尾部，开启新 context epoch。这是有意的全量前缀重写——接受一次失效，换上下文受控。checkpoint 按保留边界插入（非追加到末尾），其后保留近期尾部原文（含工具调用↔结果配对）；边界在 UI 消息粒度选取，assistant+tools 组不被切开。checkpoint 在有效上下文中以 user 轮发出，避免压缩后首条 / 连续 assistant，提升跨 provider 正确性。

M·04
动态内容尾部隔离

日期、时区、诊断等易变内容只进尾部 user 消息，绝不上前缀。前缀只装"会话内不变"的东西，这是前缀缓存能成立的前提。

M·05
子代理上下文继承

子代理通过 SubagentSessionDeps 继承主会话的 skills、memory、project-graph 和 customPrompt，注入自己的 Session Bootstrap。Bootstrap 以 role: assistant + metadata.isPrefixSystem: true 注入——Claude 提供商据此将其提取为 system 内容，避免首条消息非 user 的 400 错误；DeepSeek/OpenAI 按原样发送。
