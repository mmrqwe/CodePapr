现状五个事实

改造的出发点：原初缺口 F·03/F·04/F·05 现已修复或改善，F·01/F·02/F·06 已改造/收敛。
F·01
降级链已接入 lsp 点查询 + 文件操作（已改造）

UnifiedSymbolDispatcher 的 lsp→ast→regex 降级（Rust symbol_provider.rs 为引擎）原本只服务 project-map 符号提取。现已扩展：lsp 的 9 个导航 action 在 LSP 不可用/无结果时经 astFallback（workspaceTools.ts:2930）降级到 AST 项目图，并以 source/confidence 标注。read 的 symbol 参数用 AST 定位符号、list 逐文件 extractSymbols、grep semantic:true 走 LSP workspace symbol。write/edit/patch 也已接入 AST 语法预检与写后 LSP 诊断反馈（匹配仍为字面，歧义报错带符号定位，见 F·05）。

F·02
read 已接入 AST（已改造）

workspace_read_file 传 symbol 时先 extract_file_symbols（AST）定位符号行范围再切片返回；无 AST 支持时降级文本搜索。整文件读取超 300 行自动附带符号大纲（workspaceTools.ts:1913）。

F·03
改完没有反馈回路（已修复）

现已修复：write/edit/patch 写前跑 astPreCheck（tree-sitter，新增语法错误即拦截不落盘），写后重读校验并经 lspDiagnosticsHook 先 lsp_open_document 同步改后内容、再 lsp_get_diagnostics 按文件等待最新诊断，结果直接带 diagnostics/notes 返回。agent 改坏类型检查会在同一次工具结果里立刻看到。无 LSP 时降级并明确提示需手动复查。

F·04
graph 每次全量重建（已修复）

现已修复：buildIntelligenceProjectGraph（workspaceTools.ts:2161）外加建图缓存——按“建图参数 + 工作区”做键，TTL 60s，任一工作区写入经 notifyWorkspaceMutation 清空，同键在途构建去重，上限 3 条。lookup→dependency→impact 三连只建一次图，后两次直接复用（含昂贵的 LSP 边增强）。workspace_project_graph 也改为走该缓存（stripGraphNoise 前深拷贝以免污染缓存）。

F·05
edit 是纯字面匹配（已改善）

applySearchReplacePatch 仍以 String.indexOf 做字面匹配（searchReplaceDiff.ts），但消歧已符号化：新增 locateSearchOccurrences 返回每处行/列，多处匹配且未锁定（replaceAll/expectedOccurrences）时，edit/patch 经 extractProjectMapSymbols（AST）抛出带 L行号（位于 kind name） 的富错误，模型可精准定位而非硬猜。跨切面改名仍建议走 lsp_edit rename。

F·06
重叠的心智模型（已收敛）

原 read / graph(overview) / list 都返回结构、graph(lookup) 与 lsp(definition) 都在"找符号"、graph(impact)=dependency(incoming) 的职责重叠，现已收敛：graph 对 LLM 隐藏，项目结构归 list（目录树 + 逐文件轻量符号），点查询（定义/引用/实现/调用层级）统一进 lsp 并按需内部降级 AST。LLM 面对单一 lsp 工具，无需在重叠工具间裁决。
